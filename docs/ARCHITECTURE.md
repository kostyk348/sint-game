# Архитектура

## Принцип

Состояние — это **данные**, а не текст в контексте. Менять данные может только код.
LLM либо компилирует данные (оффлайн), либо объясняет их на естественном языке (проза),
либо переводит текст игрока в данные (интент) — но **данные применяет ядро**.

## Две фазы

### Фаза 1 — Компиляция (оффлайн)

`compile_world.py`: `lore.md → (LLM) → world.json → (валидатор) → принять/чинить`.

- LLM заполняет схему мира (см. `COMPILER.md`).
- Валидатор проверяет схему, ссылочную целостность, стартовую играбельность.
- При ошибках — до 3 раундов «верни исправленный мир».
- Результат **замораживается**: это код, а не рантайм-фантазия.

### Фаза 2 — Рантайм (детерминированно)

Каждый ход:

1. **Ввод** игрока: пункт меню (`--script`/интерактив) или свободный текст.
2. **Интент** (только для свободного текста): `parse_intent` → известное действие
   (`resolve`) или предложение нового (`propose_action`).
3. **Ворота**: любое новое действие проходит проверку (`intent.gate`).
4. **Ядро**: `World.act(id)` применяет эффекты, гоняет триггеры до фикспойнта.
5. **Проза**: LLM пишет оболочку по дельте состояния.
6. **Сейв/реплей**: состояние (включая `rng`) сериализуемо.

## Ядро (`sintgame/kernel.py`)

Состояние:

| Понятие | Где | Пример |
|---|---|---|
| Сущности | `entities[id].attrs` | `marek.hp`, `iya.trust` |
| Флаги | `flags` | `journal_found` |
| Предметы | `holds` | `("player","journal")` |
| Связи | `relations` | `("iya","player","trust",3)` |
| Триггеры | `triggers` | если `cold ≥ 100` → концовка «лёд» |

Условия (`pre`): `flag`, `not`, `gt`, `lt`, `ge`, `le`, `eq`, `has`, `rel_gt`, `rel_lt`.
Эффекты (`eff`): `set`, `add`, `flag`, `give`, `take`, `dmg`, `heal`, `rel`, `say`, `end`.
Бросок: `{"roll":"1d8","plus":"player.str","minus":"target.armor"}`.

Ключевые методы:

- `available()` — список доступных действий (по `pre`).
- `can(id)` — доступно ли конкретное действие.
- `act(id)` — исполняет **только если `pre` истинен**; иначе `[]` и `last_error="unavailable"`.
- `state()` / `restore(s)` — полный сейв, **включая `rng.getstate()`**.
- `fire()` — каскад триггеров до фикспойнта (guard 100, флаг `hit_guard`).

### Почему `act` отказывает при ложном `pre`

Кэш интента может вернуть действие, которое было валидным на прошлом ходу, но сейчас
недоступно. Ядро — последний рубеж: если `pre` ложен, действие не исполняется. То же
делает `play.py` (проверка `w.can(aid)` перед исполнением).

## Ворота (`sintgame/intent.py::gate`)

Два уровня (см. `GATE.md`):

1. **Структурные**: схема, известные сущности, `|delta| ≤ 40`, запрет `end`, непустые `eff`,
   уникальность `id`, выполнимость `pre`.
2. **Авторские инварианты**: `world.constraints.vital` + `min_hp` — сухой прогон действия
   на копии мира; если персонаж из `vital` погибает — отказ.

## Кэши и детерминизм (см. `CACHE.md`)

- **Кэш прозы** — по хешу `(тон, действие, факты, дельта)`. Даёт реплей; в режиме
  `--variety` отключается чтением (живость).
- **Кэш интента** — по хешу `(world_hash, текст)`; на попадании действие перепроверяется
  на доступность.
- **Prompt-cache нейронки** — префикс промпта байт-стабилен (только неизменяемое), всё
  изменяемое — в суффиксе. См. `sintgame/prompt.py`.

## Что где лежит

```
sintgame/kernel.py         детерминированное ядро
sintgame/schema.py         схема + валидатор + симулятор достижимости (Монте-Карло)
sintgame/search.py         ТОЧНЫЙ анализ достижимости: BFS + свидетели + мёртвые предпосылки
sintgame/prompt.py         сборка промптов со стабильным префиксом
sintgame/gen.py            адаптер LLM (SINT_GEN_CMD)
sintgame/intent.py         свободный текст → интент → ворота
sintgame/compile_world.py  лор → мир
sintgame/content.py        генерация контента (NPC/предмет/локация/квест) под верификацией
sintgame/compact.py        свёртка admitted-действий в мир (v2) + перевалидация
sintgame/memory.py         долгая память: факты (релевантные) + голоса персонажей
sintgame/editor.py         HTML-редактор мира (граф + свидетели + JSON-экспорт)
sintgame/tune.py           авто-тюнинг числовых параметров под баланс (hill-climb)
sintgame/run.py            многоэпизодный прогон N ходов с проверкой инвариантов
sintgame/sandbox.py        открытый режим: 500+ ходов без финала + директор (рост контента)
sintgame/play.py           рантайм-луп (контекстная проза: история + факты + описания)
sintgame/cache.py          каталог кэшей (.sintgame/)
sintgame/cli.py            единая точка входа
```
