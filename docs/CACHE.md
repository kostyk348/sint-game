# Кэши и детерминизм

В системе **три** разных механизма кэширования, и путать их — источник багов.
Плюс отдельно — сериализация состояния.

## 1. Проза-кэш (мой)

Ключ: `sha1(тон | действие | факты | дельта)`. Значение: сгенерированный текст.

- **Даёт реплей**: тот же ход → тот же текст.
- **Бесконтекстный**: одна и та же дельта всегда даёт один текст (повтор).
- **Живой режим** `--variety`: чтение кэша отключается, добавляется соль → разнообразие
  (но недетерминированно).

Файл: `.sintgame/prose_cache.json`.

```
replay:  проза "(cached)", состояние идентично
variety: проза "(agent-live)", состояние идентично, текст разный
```

## 2. Интент-кэш

Ключ: `sha1(world_hash | текст_игрока)`. Значение: `action_id` (+ само действие).

- `world_hash` включает мир/сущности/действия → правка мира инвалидирует кэш.
- **На попадании действие перепроверяется**: `w.can(aid)`. Если стало недоступно —
  кэш игнорируется, интент вычисляется заново. (Это закрывает баг «кэш вернул
  невалидное действие».)

Файл: `.sintgame/intent_cache.json`.

## 3. Prompt-cache нейронки (провайдера)

Провайдер кэширует KV только для **байт-идентичного префикса**. Поэтому:

```
[ PREFIX ]  неизменяемое: system + схема + title + tone + статические поля сущностей
--- граница кэша (prompt.BOUNDARY) ---
[ SUFFIX ]  всё изменяемое: состояние, меню, дельта, ввод, admitted-действия
```

Реализация — `sintgame/prompt.py`:

- `world_bible(world)` — префикс. **Исключает** `actions`, `flags`, `holds`, `relations`,
  `attrs` и рантайм-действия.
- `PrefixMonitor` — считает стабильность префикса между вызовами.
- `build(prefix, suffix)` — склейка через границу.

Все рантайм-вызовы (`parse_intent`, `propose_action`, `gen_prose`) делят **один префикс
на мир** → одна горячая запись кэша.

### Почему «весь мир в префиксе» ломает кэш

Если положить весь `world.json` в префикс, то **каждое принятое рантайм-действие** меняет
префикс и обнуляет кэш:

```
наш world_bible:  44e4b24a → admitted → 44e4b24a   STABLE
весь world JSON:  cd6c9635 →          → 9c041488   BROKEN
```

Проверяется в `tests/test_prompt_cache.py`.

### Что ещё ломает префикс

Время/nonce, случайные соли (у нас соль `--variety` — **в суффиксе**), правка system-prompt
между вызовами, переупорядочивание статики (используем `sort_keys`), интерливинг разных
миров/моделей.

> Кэш **автоматический**: мы не можем форсировать попадание, только сделать себя кэшируемыми.
> Телеметрия хоста показывает, что это работает: hit_rate ≈ 98%, но бывают промахи
> (`worst_hit_rate` почти 0) — то есть явление реально, а не теоретично.

## Состояние (не кэш, но рядом)

`World.state()` / `restore(s)`:

- флаги, атрибуты, предметы, связи, сработавшие триггеры, концовка;
- **`rng`** (`Random.getstate/setstate`).

Без `rng` сейв/лоад **рассинхронится**: продолжение пойдёт по другой ветке бросков.

```
прямой прогон 5 ударов : foe.hp = 66
2 + save + 3 удара     : foe.hp = 66
reload(save) + 3 удара : foe.hp = 66   СОВПАЛО
reload БЕЗ стейта + 3  : foe.hp = 75   РАСХОДИМСЯ (старый баг)
```

## Итог

| Механизм | Что держит | Провал, если нет |
|---|---|---|
| state + rng | состояние игры | сейв/лоад расходится |
| проза-кэш | идентичность текста при реплее | повтор при игре / нет реплея |
| интент-кэш | идентичность трактовки ввода | пересчёт, дрейф действия |
| prompt-cache | стоимость/латентность | холодный префикс каждый вызов |
