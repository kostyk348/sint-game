# Компилятор мира

`lore.md → (LLM) → world.json → (валидатор) → принять`.

## Команда

```bash
sintgame compile my_lore.md -o my_world.json [--rounds 3]
```

## Как работает

1. **Промпт** = системные правила + схема + требования + лор (`compile_world.PROMPT`).
2. **LLM** (через `SINT_GEN_CMD`) возвращает один JSON-объект.
3. **Валидатор** (`schema.validate`):
   - структура и типы;
   - ссылочная целостность (все id существуют);
   - наличие `player` с `hp`;
   - хотя бы одно доступное действие на старте;
   - корректность `constraints.vital`.
4. Если ошибки — они **возвращаются LLM** как «исправь и верни мир целиком», до `--rounds`.
5. На успехе — симуляция достижимости (`schema.simulate`): какие концовки достижимы,
   есть ли тупики, нет ли нестабильных триггеров.

## Схема мира

```jsonc
{
  "schema": 1,
  "title": "строка",
  "tone": "строка",
  "seed": 42,
  "entities": { "<id>": {"type":"", "tags":[], "attrs":{}, "desc":""} },
  "holds":    [ ["<holder>","<item>"] ],
  "relations":[ ["<from>","<to>","<type>", 0] ],
  "flags":    { "<name>": 0 },
  "actions":  [ {"id":"","label":"","pre":[COND],"eff":[EFF]} ],
  "triggers": [ {"pre":[COND],"eff":[EFF],"once":true} ],
  "constraints": { "vital": ["<id>"], "min_hp": 1 }
}
```

### COND (список, логическое И)

| Условие | Смысл |
|---|---|
| `["flag", name]` | флаг истинен |
| `["not", COND]` | отрицание |
| `["gt"/"lt"/"ge"/"le"/"eq", "<id>.<attr>"\|flag, n]` | сравнение |
| `["has", holder, item]` | у держателя есть предмет |
| `["rel_gt"/"rel_lt", from, to, type, n]` | проверка связи |

### EFF (список, по порядку)

| Эффект | Смысл |
|---|---|
| `["set", "<id>.<attr>"\|flag, v]` | присвоить |
| `["add", "<id>.<attr>", n]` | прибавить |
| `["flag", name, 0\|1]` | выставить флаг |
| `["give"/"take", holder, item]` | предмет |
| `["dmg"/"heal", id, n\|{"roll":"1d6","plus":"<id>.<attr>","minus":"…"}]` | урон/лечение |
| `["rel", from, to, type, n]` | изменить связь |
| `["say", "текст"]` | реплика/событие (идёт в прозу) |
| `["end", "<ending_id>"]` | концовка |

## Дисциплина JSON

LLM не всегда отдаёт чистый JSON. `gen.gen_json`:
- убирает markdown-заборы,
- находит первый сбалансированный `{…}` (с учётом строк и экранирования),
- при неудаче — ретрай с усиленным требованием.

## Требования, которые компилятор навязывает LLM

- игрок обязан иметь id `player` и `attrs.hp`, `hp_max`;
- ≥ 6 действий, ≥ 2 параллельные линии;
- ≥ 3 достижимые концовки;
- триггеры `once` для реакций мира;
- `constraints.vital` — кто не должен погибать.

## Что компилятор НЕ гарантирует

- **Баланс.** Числа могут быть «от балды». Настраивает автор (или симуляция).
- **Достижимость «трудных» концовок.** См. `ROADMAP.md` — случайная симуляция слаба.
- **Качество прозы.** Проза — рантайм-слой, не компилятор.

## Стабильность

Оба примера (`lighthouse`, `station`) скомпилированы **с первого прохода валидатора**.
Но выборка мала (n=2) — устойчивость на многих лорах не доказана.
