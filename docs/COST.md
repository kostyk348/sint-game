# Стоимость: сколько токенов за ход и как снизить

Измерено напрямую: `opencode run --format json "…"` печатает `usage.tokens`.

| Обёртка | total | input (свежий) | cache read | output |
|---|---|---|---|---|
| агент `build` (по умолчанию) | **12 947** | 145 | 12 800 | 2 |
| лёгкий агент [`tools/opencode/agent/sint-gen.md`](../tools/opencode/agent/sint-gen.md) | **2 174** | 2 147 | 0 | 2 |

**Вывод:** почти всё — это системный промпт агента-обёртки, а не наш промпт. Наш вклад:
`world_bible` ≈ 1 100 токенов + суффикс 50–200. Лёгкий агент (без инструментов) снижает
расход **в ~6 раз**.

## Сколько за ход

| Режим хода | Вызовов LLM | Токенов |
|---|---|---|
| по меню (`--script`/интерактив) | 1 (проза) | ~2–13k |
| свободный текст, действие найдено | 2 (интент + проза) | ~4–26k |
| свободный текст, действие новое | 3 (+ предложение) | ~6–40k |
| **повтор хода (реплей)** | 0 (кэш прозы) | **0** |

## Как снизить

1. **Лёгкий агент** (6×):

   ```bash
   mkdir -p .opencode/agent
   cp tools/opencode/agent/sint-gen.md .opencode/agent/
   export SINT_GEN_CMD="opencode run --agent sint-gen --pure"
   ```

2. **Проза-кэш**: идентичный ход (тон+действие+факты+дельта+контекст) не вызывает LLM — 0.
3. **Prompt-cache**: `world_bible` стабилен → провайдер кэширует префикс (см. `CACHE.md`).
4. **Перспектива**: прямой вызов API без агент-обёртки — убирает и ~2k оверхед.

## Тонкость про деньги

`build` тратит 12.8k, но это **cache read** (провайдер берёт за него в разы меньше).
`sint-gen` тратит 2.1k, но это **свежий input** (полная цена). Поэтому *стоимость* вызова
может быть сопоставима, а вот **число токенов и латентность** у лёгкого агента в разы ниже.
Если важна цена — считайте по своему тарифу (cache-hit vs cache-miss), а не по «total».

## Что НЕ тратит токены

- Детерминированное ядро (состояние, триггеры, броски) — 0.
- Валидатор, анализ достижимости, баланс, компакция — 0 (чистый Python).
- Реплей из кэша — 0.

## Одно прохождение примера: измерено

**Что считается одним прохождением.** Документированный прогон `examples/lighthouse` до
концовки: `play --script talk_iya,press_marek,search_cabin,reveal_truth --prose none`
— 4 хода, финал `truth` (см. README, раздел «Быстрый старт»).

**Стенд.** opencode 1.18.35, модель `opencode/big-pickle`, Python 3.14.7, 14.10.2026.
`SINT_GEN_CMD` — обёртка над `opencode run --pure --format json`, которая отдаёт движку
только текст, а `usage` пишет в журнал.

### Запросы к модели

| Режим | Запросов на прохождение |
|---|---|
| меню/`--script`, 4 хода | **4** — ровно один на ход |
| свободный ввод, 1 ввод | **3** (интент → предложение действия → проза) |
| меню, `--prose none` | **0** (движок оффлайн) |
| повтор того же хода из кэша прозы | **0** — с оговоркой про hash seed ниже |
| `--variety` | 1 на ход (кэш отключён) |

Числа сняты инструментированной заглушкой в `SINT_GEN_CMD` (пишет каждый промпт в файл
и печатает фиксированный текст): 4 хода → 4 записи в журнале, лишних вызовов нет.

### Токены

Вклад самого движка — измерено на фактических промптах этих четырёх запросов
(`tiktoken`, `cl100k_base` как воспроизводимый прокси):

| Запрос | промпт, символов | токенов (cl100k) |
|---|---|---|
| 1 | 4 613 | 2 052 |
| 2 | 4 665 | 2 099 |
| 3 | 4 878 | 2 172 |
| 4 | 5 019 | 2 246 |
| **итого** | | **8 569** |

То есть **~2.1 тыс. токенов на ход**, ~8.6 тыс. на прохождение — это всё, что движок
добавляет к системному промпту обёртки.

Что реально уходит провайдеру (дословный `usage` из журнала):

| Запрос | total | input (свежий) | cache read | output | секунд |
|---|---|---|---|---|---|
| 1 | 299 015 | **294 377** | 4 096 | 114 | 23.3 |
| 2 | 298 604 | 633 | 297 856 | 74 | 24.6 |
| 3 | 298 875 | 694 | 297 856 | 98 | 23.4 |
| 4 | 299 016 | 765 | 297 856 | 113 | 24.8 |

**Прохождение целиком: 4 запроса, 1 м 37 с.** Первый ход — холодный кэш (~294 тыс. свежих
токенов), дальше ~99.8 % промпта приходит из prompt-кэша провайдера, свежих токенов остаётся
меньше тысячи на ход. Наша часть (~2 тыс. токенов) — ~0.7 % того, что видит провайдер.

Для сравнения: свободный ввод («обнять Ию, она плачет» → ворота приняли новое действие
`hug_iya` → проза) — **3 запроса, 41.7 с**; без LLM (`--prose none`) тот же прогон — **0 запросов**.

### Чего в этих числах нет

- **Денег.** В этих прогонах `usage` пришёл без поля `cost`. Единичный пробный вызов
  opencode вернул `cost: 0.0379` на холодные ~255 тыс. токенов — считайте по своему тарифу.
- **Нарезки конкретной модели.** `cl100k_base` здесь — прокси; у провайдера своя.
- **Выигрыша «лёгкого агента» в 6×.** На этом стенде он **не воспроизводится**: с агентом
  `sint-gen` оверхед упал с 296 320 до 282 240 кэш-read токенов, то есть на ~4.7 %, а не в
  разы. Причина: 280–290 тыс. токенов — это системный промпт и схемы инструментов самой
  обёртки `opencode` (агент `build`), а не наш промпт; минимальный конфиг без MCP-серверов
  цифру не меняет. Таблица «12 947 → 2 174» выше снята на другой версии/конфигурации
  opencode, и её пропорция сюда не переносится. Вывод «свой промпт — это ~2 % расхода, всё
  остальное решает выбор обёртки» остаётся в силе.

### Оговорка: реплей = 0 только при стабильном порядке фактов

Кэш прозы даёт 0 запросов на повтор хода **только если ключ совпал**. Ключ включает список
фактов, а список собирается обходом множества → при другом `PYTHONHASHSEED` порядок другой,
ключ другой, и повтор снова уходит в модель. Воспроизведение: два одинаковых прогона с
`PYTHONHASHSEED=0` дают байт-идентичные промпты (`md5` = `9bc384f3…`), а с `PYTHONHASHSEED=1`
— другие (`md5` = `25f5a9b5…`). Внутри одного процесса реплей работает как заявлено.
