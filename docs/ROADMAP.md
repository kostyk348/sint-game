# Roadmap

Честная карта: что уже есть, чего нет, что делать дальше. Порядок — по ценности/риску.

## Есть (ядро)

- Детерминированное ядро (сущности/атрибуты/флаги/предметы/связи/триггеры/концовки).
- Компилятор `lore → world` (LLM) под валидатором.
- Валидатор (схема + инварианты + симуляция достижимости).
- **Точный анализ достижимости** (BFS со свидетелями): `search.py` доказывает достижимость
  конструктивно (последовательность действий) и находит мёртвые предпосылки.
- Ворота (структурные + `constraints.vital`).
- Свободный текст → интент → действия (с воротами); сопоставление с существующими
  действиями (без дублей) + оффлайн-деградация.
- Проза LLM + кэш + `--variety` + **контекстная** (`--context N`; история и описания сущностей).
- **Создание контента** (`sintgame add`): NPC/предмет/локация/квест в существующий мир под
  верификацией (схема + мёртвые предпосылки + сохранение достижимости).
- **Долгая память** (факты по релевантности + голоса `voice`); **компакция** (`compact`);
  **диагностика** пространства состояний (`diagnose`).
- **Инструменты автора**: редактор (`editor`), баланс (`balance`), тюнинг (`tune`),
  многоэпизодный прогон с проверкой инвариантов (`run`).
- **Открытый песочный режим**: миры без концовок (`compile --sandbox`), непрерывные прогоны
  500+ ходов (`sandbox`), директор (рост контента в рантайме под воротами).
- Валидатор ловит **петли триггеров** (стабильность).
- Сейв/лоад состояния с `rng`.
- Дисциплина prompt-кэша (стабильный префикс).
- 4 примера-мира (lighthouse, station, campaign, sandbox), 45 тестов.

## Нет (до «полноценной игры»)

### Ближайшее (инженерное)

1. **Исчерпание пространства при числовых атрибутах.** BFS даёт свидетелей достижимости, но
   при многих числовых атрибутах пространство состояний не исчерпывается → «недостижимость»
   не доказывается. Нужна абстракция по порогам (трекинг только значений, релевантных
   условиям) или символьный анализ. Инструмент `sintgame diagnose` уже показывает, какие
   атрибуты раздувают пространство. (Базовый BFS + свидетели — сделано.)
2. ~~Компакция мира~~ — **сделано**: `sintgame compact` (свёртка `.ext.json` в v2 + перевалидация).
3. **Variant-salt прозы** как явный механизм (сейчас `--variety` рубит кэш целиком;
   нужен аккуратный «детерминизм для реплея + разнообразие для игры»).
4. **Расширение словаря действий/эмоций** под free-text. Частично сделано (сопоставление с
   существующими действиями). Остаётся: «обнять» → «поговорить» там, где нет действия под
   эмоцию; richer intent-схемы (соц. рамка, интенсивность) и словари автора.

### Дальше (продуктовое)

5. **Длинная память.** Сделано: окно `--context`, факты, `voice`, соак `run` на 50+ ходов,
   **сохранение памяти между сессиями** (`--save/--load`, `sintgame memory`). Осталось:
   **семантическая** проверка дрейфа характера.
6. ~~Редактор / инструмент автора~~ — **сделано**: `sintgame editor` (HTML: граф + свидетели +
   JSON). Дальше: WYSIWYG-правка структуры (сейчас через JSON-вкладку).
7. ~~Балансировка через симуляцию~~ — **сделано**: `balance` + `tune` (числовой).
   Дальше: структурный авто-рефактор (когда дисбаланс не числовой).
8. **Мультимир / кампании** — несколько миров, перенос состояния, общая шина контрактов.
9. **Низколатентный инлайн-вызов LLM** вместо `opencode run` (для тесной интеграции).

## Открытые вопросы (продуктовые)

- **Трек.** Это пивот или отдельный проект? Третий активный трек повышает риск, что один
  умрёт тихо. Решение владельца.
- **Граница «живости».** Детерминизм vs разнообразие — фундаментальное противоречие;
  снимается только двумя режимами (replay/live).
- **Что отгружаем первым.** Киоск-миры (сценарии) или редактор для авторов?

## Метрики, по которым судить

- Доля концовок, достижимость которых **доказана** (не «найдена случайно»).
- Стабильность префикса (prompt-cache hit rate).
- Консистентность голоса: доля реплик персонажа, не противоречащих характеру, на дистанции.
- Доля действий, предложенных LLM, которые **прошли ворота** (слишком низкая → ворота
  душат; слишком высокая → мир не защищён).
